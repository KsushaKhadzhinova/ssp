## 3. Теория коротко

**Рефлексия** – получение информации о типах во время выполнения и работа с ними (создать объект, вызвать метод,
прочитать поле) по метаданным сборки. Пространство имен `System.Reflection`.

**Три способа получить Type:**
- `typeof(Product)` – на этапе компиляции, объект не нужен;
- `obj.GetType()` – фактический тип объекта во время выполнения (может быть наследником);
- `Type.GetType("LabReflection.Product")` – по строке, это и есть позднее связывание.

**Классы:** `Type`, `Assembly`, `MemberInfo`, `FieldInfo`, `PropertyInfo`, `MethodInfo`, `ConstructorInfo`,
`ParameterInfo`, `Activator`, `BindingFlags`, `Attribute`.

**BindingFlags:**
- `Public` / `NonPublic` – открытые / закрытые (private, protected, internal);
- `Instance` / `Static` – обязательно указать хотя бы один вместе с Public/NonPublic, иначе пусто;
- `DeclaredOnly` – без унаследованных (без `ToString`, `Equals` и т.п.);
- без флагов `GetMethods()` = `Public | Instance | Static`.

**Чтение/запись:**
- поле: `type.GetField("_x", NonPublic | Instance)` → `GetValue(obj)` / `SetValue(obj, value)`;
- свойство: `GetProperty("Id")` → `GetValue` / `SetValue`;
- метод: `GetMethod("Add", new[] { typeof(int), typeof(int) })` → `Invoke(obj, new object[] { 1, 2 })`;
- статический член: в `GetValue`/`Invoke` вместо объекта передается `null`;
- перегрузки различаются массивом типов параметров.

**Создание объекта:** `Activator.CreateInstance(type)`, `Activator.CreateInstance(type, args)`,
`type.GetConstructor(new[] { typeof(int) }).Invoke(new object[] { 42 })`.

**Делегат из MethodInfo:** `(Func<int,int,int>)method.CreateDelegate(typeof(Func<int,int,int>), obj)` –
связывание один раз, дальше вызов быстрый, без упаковки аргументов в `object[]`.

**Атрибуты:** класс `: Attribute`, `[AttributeUsage(AttributeTargets.Class)]`,
читаются `type.GetCustomAttribute<PluginAttribute>()` (null, если атрибута нет).

**Раннее связывание** – компилятор знает тип и метод, проверяет и делает прямой вызов.
**Позднее** – тип и метод по имени во время выполнения, ошибки только при запуске, медленнее.

**Почему видны get_Id, set_Id и <Id>k__BackingField:** свойство = пара методов `get_`/`set_` (у них `IsSpecialName = true`),
автосвойство хранит значение в скрытом поле, которое генерирует компилятор.

## 5. Задание 7: как работает загрузка плагинов

1. `Assembly.GetExecutingAssembly().GetTypes()` – все типы сборки.
2. Фильтр: `typeof(IPlugin).IsAssignableFrom(t) && !t.IsInterface && !t.IsAbstract`.
3. Фильтр по атрибуту: `t.GetCustomAttribute<PluginAttribute>() != null`.
4. Читаем `plugins.config` (строки с `#` – комментарии), ищем тип по `FullName`.
5. `Activator.CreateInstance(type)` → приводим к `IPlugin` → `Execute()`.

Новый плагин = новый класс с `[Plugin("...")]` + строка в `plugins.config`; код `Task7` не меняется.

В доп. задании метод `LoadBuiltInPlugins()` добавлен, чтобы загрузить плагины из текущей сборки
(методичка показывает вывод «Loading built-in plugins...»); `LoadPlugins()` из папки Plugins тоже вызывается, папка пустая.

## 6. Ответы на контрольные вопросы

1. Рефлексия – доступ к метаданным типов во время выполнения; плагины, сериализация, ORM, DI, тесты.
2. `System.Reflection` (Assembly, FieldInfo, MethodInfo, PropertyInfo, ConstructorInfo, BindingFlags), `System.Type`, `System.Activator`.
3. `typeof` – по имени типа при компиляции; `GetType()` – у объекта, реальный тип при выполнении.
4. `GetField/GetMethod` с `BindingFlags.NonPublic | BindingFlags.Instance`, затем `GetValue/SetValue/Invoke`.
5. Риски: ломает инкапсуляцию, ошибки только при запуске, хрупкость при переименовании, медленно, проблемы с trimming/AOT.
6. `BindingFlags` – какие члены искать (доступ, static/instance, только объявленные, регистр).
7. `Activator.CreateInstance(type[, args])` или `ConstructorInfo.Invoke`.
8. Раннее – при компиляции, проверено и быстро; позднее – при выполнении по имени.
9. Медленно, нет проверки компилятором, упаковка аргументов, нарушение инкапсуляции, сложнее сопровождать.
