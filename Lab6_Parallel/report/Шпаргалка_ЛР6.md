## 3. Теория коротко

**TPL** (`System.Threading.Tasks`): `Task`, `Task<TResult>`, `Parallel.For/ForEach/Invoke`, `TaskScheduler`,
`CancellationToken`. Работает поверх пула потоков, сама подбирает число потоков.

**Parallel.For(0, N, i => ...)** – по индексам. **Parallel.ForEach(collection, item => ...)** – по элементам
любой `IEnumerable<T>` или по разделам `Partitioner`.

**Перегрузка с локальными данными** (главная идея лабы):
```csharp
Parallel.For(0, N,
    () => 0.0,                                  // localInit: своя переменная у каждого потока
    (i, state, local) => local + f(i),          // body: без блокировок
    local => { lock (o) total += local; });     // localFinally: один lock на поток
```

**ParallelLoopState:** `state.Break()` – не начинать итерации с большим индексом,
`state.Stop()` – остановить как можно скорее. **Отмена:** `ParallelOptions { CancellationToken = cts.Token }`,
`cts.Cancel()` → `OperationCanceledException`.

**PLINQ:** `data.AsParallel()...` – параллельный LINQ. `WithDegreeOfParallelism(n)` – максимум потоков,
`AsOrdered()` – сохранить порядок (дороже), `ForAll` – без слияния результатов.
Порядок по умолчанию не гарантируется.

**Разделение данных:** на диапазоны (массивы), блочное (динамическая балансировка), хеш (по ключу).
`Partitioner.Create(0, N, 100000)` – диапазоны `Tuple<int,int>` по 100 000, тело вызывается раз на блок.

**Агрегация:** локальная переменная + одна синхронизация (`lock`, `Interlocked.Add`) или операторы PLINQ
`Sum/Average/Aggregate`. `Interlocked.Add(ref x, v)` – атомарное сложение без lock.

**Почему lock на каждой итерации медленно:** 10 млн захватов, потоки ждут друг друга, переключения контекста,
строка кэша с общей переменной «прыгает» между ядрами (false sharing / contention).

**Когда параллелить:** много данных, дорогая операция на элемент, итерации независимы, мало синхронизации.
Для дешевых операций накладные расходы больше выигрыша.

запуск потоков, слияние частичных средних и первый JIT. Вывод проверен вариантом 2: при дорогой проверке
простоты PLINQ дает 7,5×.

Почему `Break()` в интерактивном поиске может вернуть не первую позицию: потоки идут по разным диапазонам,
`pos` записывает тот поток, который нашел раньше по времени.

## 6. Ответы на контрольные вопросы

1. **TPL** – библиотека параллелизма в `System.Threading.Tasks`: Task, Task<T>, Parallel, планировщик, отмена, PLINQ.
2. **For vs ForEach** – For по целочисленному диапазону, ForEach по элементам коллекции/разделам.
3. **PLINQ vs LINQ** – PLINQ делит данные и выполняет запрос на нескольких ядрах (`AsParallel`), порядок не гарантирован.
4. **Стратегии разделения** – диапазоны, блоки, хеш; `Partitioner.Create`.
5. **Агрегация** – локальные для потока переменные + одна синхронизация в конце (`lock`/`Interlocked`), или Sum/Aggregate в PLINQ.
6. **Когда параллелить** – большие данные, затратная независимая работа, несколько ядер; иначе быстрее последовательно.
