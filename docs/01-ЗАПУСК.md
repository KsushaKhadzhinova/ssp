# ССП, лабораторная работа 2. Как запустить

Тема: **Управление памятью в C# и анализ утечек** (сборщик мусора, поколения, LOH, утечки, упаковка). Код в папке `Lab2`.

## Что установить

| Что | Зачем | Проверка |
|---|---|---|
| **.NET SDK 10** | сборка и запуск | `dotnet --version` |
| **dotnet-gcdump** (по желанию, для снимков памяти) | «фотографии» кучи | `dotnet tool install --global dotnet-gcdump`, затем `dotnet-gcdump --version` |
| VS Code (C# Dev Kit) или Visual Studio 2022 | показывать код | |

## Запуск

```bash
git clone https://github.com/KsushaKhadzhinova/ssp.git
cd ssp
git checkout lab-2
cd Lab2
dotnet run -c Release
```

**Важно:** запускайте в режиме **Release** (`-c Release`). В Debug локальные переменные «живут» дольше и результаты сборки мусора отличаются.

Выполнятся: демонстрация статической ссылки, задание 1, задания 2–3, задания 4, 5, 6.

### Задание 7 (отдельно)

```bash
dotnet run -c Release -- task7
```

Задание 7 держит около 1 ГБ памяти (1000 объектов по 1 МБ в «плохой» версии), поэтому запускается отдельно, чтобы не искажать остальные замеры. Нужно около 1,5 ГБ свободной памяти.

### Три снимка памяти (snapshots)

В режиме `snapshots` программа останавливается на трёх этапах и ждёт нажатия Enter.

1. **Окно 1:** `dotnet run -c Release -- snapshots`. Программа напечатает `READY` и будет ждать.
2. **Окно 2:** узнать номер процесса: `dotnet-gcdump ps` (найти `Lab2`). Снять снимок: `dotnet-gcdump collect -p <номер> -o snapshot1.gcdump`.
3. В **окне 1** нажать Enter; программа выполнит этап 2 (утечки и LOH) и снова напечатает `READY`. Снять `snapshot2.gcdump`.
4. Enter; этап 3 (отписка и очистка). Снять `snapshot3.gcdump`. Enter – завершение.
5. Прочитать снимок: `dotnet-gcdump report snapshot2.gcdump`. В таблице смотрите строки `System.Byte[]` и общий размер кучи (`GC Heap bytes`).

Методичка называет профилировщики **dotMemory** или **Visual Studio Diagnostic Tools**. Если они есть, делайте снимки в них: запустить приложение, нажать «Take snapshot» на каждом этапе. `dotnet-gcdump` даёт тот же результат в текстовом виде.

## Что вы увидите

- Статический список: общий для объектов; экземплярный – свой.
- Рост памяти при создании утечек и **отсутствие** падения после `GC.Collect()`.
- После отписки от события память возвращается.
- Объекты больше 85 000 байт сразу в Gen2 (LOH).
- Упаковка (`List<object>`) в десятки раз медленнее `List<int>` и занимает больше памяти.
- Задание 7: «плохой» класс держит ~1002 МБ и 1001 объект в кэше, исправленный не держит ничего.
