# ССП, лабораторная работа 1. Как запустить

Тема: **Платформа .NET: анализ IL-кода и JIT-компиляции**. Код находится в папке `Lab1`.

## Что нужно установить (один раз)

| Что | Зачем | Как проверить |
|---|---|---|
| **.NET SDK 10** (или новее) | компилятор и запуск C# | `dotnet --version` (должно быть `10.x`) |
| **Интернет** при первом запуске | скачивается пакет BenchmarkDotNet | сообщение `Restored ...` |
| Любой редактор: **VS Code** (расширение C# Dev Kit) или **Visual Studio 2022** | чтобы показывать код | |

Если `dotnet` не найден, закройте и заново откройте терминал (после установки меняется `PATH`).

## Запуск из терминала

```bash
git clone https://github.com/KsushaKhadzhinova/ssp.git
cd ssp
git checkout lab-1
cd Lab1
dotnet run
```

`dotnet run` сам собирает проект (в режиме Debug) и запускает его. Выполняются задания 1, 2 и 4: анализ IL, генерация методов, исследование JIT.

### Задание 3 (BenchmarkDotNet)

Бенчмарки нужно запускать **в режиме Release**:

```bash
dotnet run -c Release -- bench
```

`-c Release` – режим сборки, `--` отделяет параметры самой `dotnet` от параметров программы, `bench` – аргумент, по которому `Program.cs` запускает анализаторы. Выполнение занимает около минуты. В конце выводятся таблицы со средним временем (столбец `Mean`).

## Запуск в редакторе

- **VS Code:** `File → Open Folder` → выбрать папку `Lab1`. Открыть `Program.cs`, внизу справа выбрать проект, нажать `Ctrl+F5` (запуск без отладки) или в терминале выполнить `dotnet run`.
- **Visual Studio 2022:** `File → Open → Project/Solution` → файл `Lab1.csproj`; `Ctrl+F5`. Для задания 3 в панели сверху выбрать **Release** и в свойствах проекта (`Debug`) указать аргумент командной строки `bench`.

## Что вы увидите

1. Для каждого из трёх методов – размер IL в байтах, число локальных переменных, максимальный размер стека и **байты IL в шестнадцатеричном виде**.
2. Задание 1 – IL-байты метода `Multiply`: `02 03 5A 2A`.
3. Результаты динамически созданных методов (`DynamicAdd(15, 27) = 42` и т. д.).
4. Результаты заданий 2.1 и 2.2 (рекурсивный факториал и максимум из трёх).
5. Измерение времени вызовов и сравнение «первый вызов с JIT» и «повторный вызов».

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `Тело метода не доступно (Release режим?)` | запустите без `-c Release` (Debug) для заданий 1 и 2: в Release компилятор оптимизирует и размеры IL меняются |
| ошибка восстановления пакетов NuGet | нет интернета: подключитесь к сети и повторите `dotnet restore` |
| `bench` работает очень долго | это нормально (около минуты на два класса) |
| числа времени отличаются от отчёта | у каждого компьютера свои значения; важны соотношения |
