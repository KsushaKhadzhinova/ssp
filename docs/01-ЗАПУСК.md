# ССП, лабораторная работа 4. Как запустить

Тема: **Поиск утечек памяти и профилирование производительности в C#**. Код в папке `Lab4`.

## Что установить

| Что | Зачем | Проверка |
|---|---|---|
| **.NET SDK 10** | сборка и запуск | `dotnet --version` |
| VS Code (C# Dev Kit) или Visual Studio 2022 | показывать код | |

## Запуск (три режима)

```bash
git clone https://github.com/KsushaKhadzhinova/ssp.git
cd ssp
git checkout lab-4
cd Lab4
dotnet run -c Release
```

| Команда | Что выполняется |
|---|---|
| `dotnet run -c Release` | базовый код методички и задания 1, 2, 3 |
| `dotnet run -c Release -- buggy` | задание 4: `BuggyCode` и `FixedCode` (100 объектов по 1 МБ ≈ 100 МБ) |
| `dotnet run -c Release -- calltree` | профилирование: Call Tree с `DateTime.TryParse`, с `DateTime.ParseExact` и профиль собственного кода |

Всегда используйте **Release**: в Debug результаты сборки мусора и скорость отличаются.

## Что вы увидите

1. Базовый код: статические ссылки, выделение памяти, утечки, упаковка, очистка, поколения.
2. Задание 1: статическая утечка (память не уходит после `GC.Collect()`) и событийная утечка (уходит после отписки).
3. Задание 2: объекты 80 000 и 90 000 байт (Gen0 и Gen2/LOH).
4. Задание 3: `List<object>` против `List<int>`; `ArrayList` против `List<int>`.
5. Задание 4: «плохой» класс держит 100 объектов в кэше и ≈ 100 МБ, исправленный не держит.
6. Call Tree: дерево времён методов, горячий путь, статистика вызовов.
7. Профиль собственного кода: конкатенация строк занимает почти всё время.

## Важно: исправление ошибки в примере методички

Пример Call Tree из методических указаний при запуске «как есть» **падает** с `KeyNotFoundException: IsAnomaly.Checks`: дата берётся из `parts[1]` (там уровень `INFO`/`ERROR`), поэтому `DateTime.TryParse` всегда возвращает `false`. В нашей версии дата берётся из `parts[0]` после префикса `USERnn:`, время хранится как `double`, перед замерами выполняется прогрев (описано в отчёте).
