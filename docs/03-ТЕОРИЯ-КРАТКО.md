# ССП-4. Теория кратко

- **Виды утечек:** статические ссылки; неотписанные события; неосвобождённые `IDisposable`; зацикленные ссылки.
- **Горячий путь** – цепочка методов с наибольшей долей времени (Call Tree). Не утечка, а узкое место.
- **Call Tree:** дерево «кто кого вызвал + время + доля от родителя».
- **Own time** – время самого метода без вложенных; **total time** – вместе с вложенными.
- **Профилирование** – измерять, потом оптимизировать узкое место.
- Поколения Gen0/1/2; LOH для объектов **> 85 000 байт** (нет уплотнения → фрагментация).
- **Boxing**: `List<object>`/`ArrayList` медленнее и «тяжелее» `List<int>` в разы.
- `BuggyCode`: подписка на статическое событие без отписки + статический кэш `MemoryStream` + массив 1 МБ в каждом объекте → утечка; исправление – `IDisposable`: `-=`, `Remove`, `Dispose()`.
- **Результаты:** статическая утечка не уходит после GC; событийная уходит после отписки; массив 90 000 байт – Gen2; конкатенация строк ≈ 97 % времени своего профиля; `ParseExact` не быстрее `TryParse`.
