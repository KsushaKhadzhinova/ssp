# ССП на Mac: что установить, как настроить и что сказать

Лабораторные ССП (C#, .NET 10) на Mac запускаются так же, как на Windows. Единственное отличие – установка .NET SDK и пара мелочей.

## 1. Что установить (один раз)

| Что | Как | Проверка |
|---|---|---|
| **.NET SDK 10** | установщик с dotnet.microsoft.com/download (выбрать macOS, свою архитектуру: Arm64 = Apple Silicon, x64 = Intel) или `brew install --cask dotnet-sdk` | `dotnet --version` – версия `10.x` |
| **git** | при первом вызове `git` Mac предложит установить Command Line Tools – согласиться | `git --version` |
| **Редактор** (по желанию) | VS Code + расширение C# Dev Kit | |
| **dotnet-gcdump** (только лаб. 2 и 4, снимки памяти) | `dotnet tool install --global dotnet-gcdump` | `dotnet-gcdump --version` |

Если `dotnet` не находится после установки – закрыть и заново открыть Терминал. Для `dotnet-gcdump` может понадобиться добавить в `PATH` папку `~/.dotnet/tools`: `echo 'export PATH="$PATH:$HOME/.dotnet/tools"' >> ~/.zshrc`, затем открыть новое окно Терминала.

## 2. Получить и запустить

Каждая работа лежит в своей ветке (`lab-1` … `lab-4`):

```bash
git clone https://github.com/KsushaKhadzhinova/ssp.git
cd ssp
git checkout lab-1
cd Lab1
dotnet run -c Release
```

Особые режимы те же, что на Windows: `Lab1` – `dotnet run -c Release -- bench`; `Lab2` – `-- task7`, `-- snapshots`; `Lab4` – `-- buggy`, `-- calltree`.

## 3. Чем Mac отличается

| Что | Особенность |
|---|---|
| Пути к файлам | вместо `\` – `/` (в коде используется `Path.Combine`, поэтому всё работает) |
| Размер памяти и время | цифры будут другими (другой процессор и ОС) – это нормально, выводы те же. Для отчёта используйте цифры, полученные на ноутбуке, на котором делался отчёт, а на Mac показывайте, что программа работает |
| Блокировка macOS («нельзя открыть, так как разработчик не подтверждён») | относится к скачанным приложениям; `dotnet run` из Терминала её не вызывает |
| Бенчмарки | запускать только `-c Release`, пока ноутбук подключён к питанию и ничего тяжёлого не запущено |
| Лаб. 1, `unsafe`-код | работает на Mac без изменений |

## 4. Что сказать на защите про Mac

> «Платформа .NET кроссплатформенная: компилятор превращает C# в IL-код, а JIT-компилятор уже на конкретном компьютере (Windows, macOS или Linux; Intel или Apple Silicon) переводит его в машинный код этого процессора. Поэтому одни и те же исходники я запускала и на Windows, и на Mac; различаются только цифры времени и памяти».

Если спросят «почему цифры другие?»: разные процессор, кэш, версия ОС и состояние ступенчатой (tiered) JIT-компиляции; поэтому для сравнения вариантов кода используют **одну и ту же машину и режим Release**.

Порядок показа на защите смотрите в `docs/05-ЗАЩИТА.md` соответствующей ветки.
